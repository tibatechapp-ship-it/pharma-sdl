# RYKO — العقل العلمي لمنصة Pharma SDL

**الخطة الشاملة المحكمة علمياً — الإصدار P19 (v0.19.0) · 2026-11**

> **Ryko** هو الذكاء العلمي للفارما داخل Pharma SDL: طبقة حسابية **حتمية، مُوثّقة، وقابلة للتحقق دون اتصال** تغطي الرياضيات والفيزياء والكيمياء والصيدلانيات والفارماكولوجيا — ثم الأمراض والتشخيص في المرحلة الثانية. كل رقم يخرج من Ryko يحمل معه: المعادلة، والمصدر، والافتراضات، وبصمة SHA-256 قابلة لإعادة الحساب.

---

## 1. الرؤية والهوية

Pharma SDL امتلك خط اكتشاف كاملاً (تنقية ← فرز ← فعالية ← ربط ← ADMET ← قرار ← تقرير)، لكن القرار العلمي يتطلب **عقلاً** يجيب عن أسئلة ما بعد الفحص: ما عمر النصف؟ ما الجرعة؟ ما الانحلال؟ ما احتمال الاختبار البعد الإيجابي؟

**Ryko = هذا العقل.** ليس نموذج لغة يخمّن، بل **محرك معادلات مُعلَنة المصدر** — فلسفة المنصة نفسها («كل رقم مصدره معلن، وتدهوره صادق») مطبَّقة على المعرفة الصيدلانية الأساسية.

| الخاصية | الالتزام |
|---|---|
| **حتمية بالبايت** | نفس المدخلات = نفس الناتج = نفس البصمة (SHA-256). لا عشوائية ولا طوابع زمنية في البصمة. |
| **إيصال قابل للتحقق** | كل عملية تعيد إيصالاً (قيمة + معادلة + مصدر + افتراضات) يُعاد التحقق منه دون اتصال — اكتشاف التلاعب اختبار ملزم. |
| **عربي أولاً** | كل وصف عملية ورسالة خطأ ثنائي اللغة (عربي/إنجليزي). |
| **بلا شبكة ولا مفاتيح** | المرحلة الأولى محرك حتمي صافٍ — لا Ollama ولا API خارجي. |
| **تدهور صادق** | مدخل خارج النطاق = خطأ مُعلَّل ثنائي اللغة، لا رقم مُختلق ولا صمت. |
| **ارتباط وثيق بالمنصة** | Ryko يعيش داخل `pharma_sdl/`، يُنشر عبر بوابة API نفسها، ويُغطى بنفس CI ونفس حارس اتساق الإصدار. |

## 2. ما نأخذه من ZYKO (انتقاء مُعلن — لا نسخ كامل)

فُحص مستودع `tibatechapp-ship-it/zyko` (v0.39.0، 2816 اختباراً)، واعتُمد **أربعة مفاهيم معمارية فقط** — الأنسب لعقل فارما — ووُضعت على قياس منصتنا:

| # | مفهوم ZYKO | الترجمة في Ryko |
|---|---|---|
| 1 | **الإيصال القابل للتحقق بالبناء** (`zyko verify` يعيد حساب أي قرار دون اتصال) | `RykoReceipt` + `verify_stored()` — إعادة حساب البصمة من حقول الإيصال، واكتشاف أي تلاعب حرفيّ |
| 2 | **الحتمية بالبايت** (نفس المدخل = نفس المخرج، SHA-256) | تحميل JSON بمفاتيح مرتّبة، تقريب عشري مُثبَّت، صفر طوابع زمنية في البصمة |
| 3 | **الحاكم قبل التنفيذ** (ALLOW/DENY/REVIEW قبل كتابة بايت) | **بوابة التحقق قبل الحساب**: نطاقات فيزيائية ملزمة (ke>0، T>0،scr>0،EC50>0…) — خارج النطاق = DENY مُعلَّل |
| 4 | **عقول خلف بوابات نفسها** (حتمي أولاً، نموذج محلي/سحابي لاحقاً خلف نفس الحاكم) | المرحلة 1 عقل حتمي صافٍ؛ المرحلة 2+ تسمح بنموذج مساعد **لا يخرج رقم إلا بمعادلة ومصدر** عبر نفس الإيصال |

**ما لم نأخذه** (ومراجع القرار): محرك توليد الكود العربي (`daad`) وتحليل التلوث AST وMCP وواجهة الأندرويد — هذه لموّل ZYKO البرمجي، لا لعقل فارما علمي. الانتقاء قرار معماري مُعلن: نبني العقل العلمي على DNA المنصة نفسها.

## 3. المرحلة الأولى — الوحدات الخمس (P19: منفَّذة في هذا الإصدار)

كل وحدة: **مدخلات مُعلنة + معادلات بمصادرها + حدود نطاق + أمثلة تحقق ذهبية مُحسوبة يدوياً**.

### U1 — `math_core` : الرياضيات والحساب الدوائي

| العملية | المعادلة | المصدر |
|---|---|---|
| `convert` | تحويل الوحدات (كتلة/حجم/مول عبر الكتلة المولية) | SI |
| `auc_trapz` | AUC = Σ (C₁+C₂)/2 × Δt (شريطية؛ ذيل لوغاريتمي اختياري) | Gabrielsson & Weiner، PK/PD Data Analysis |
| `half_life` / `ke_from_half_life` | t½ = ln(2)/kₑ | السمعي الحتمي؛ Rowland & Tozer، Clinical PK |
| `clearance` | CL = Dose/AUC | Rowland & Tozer |
| `volume_distribution` | Vd = CL/kₑ | Rowland & Tozer |
| `bioavailability` | F = (AUCpo/AUCiv)×(Doseiv/Dosepo) | Rowland & Tozer |
| `ci95_mean` | x̄ ± t(0.975, n−1)·s/√n | scipy.stats (مثبتة الإصدار) |
| `linear_fit` | أقل مربعات: ميل/تقاطع/R² | إغلاقية، بلا اعتماد خارجي |

### U2 — `physics_core` : الفيزياء (ديناميكا حرارية وانتقال)

| العملية | المعادلة | المصدر |
|---|---|---|
| `binding_dg` / `kd_from_dg` | ΔG = RT·ln(Kd) (Kd بالمولار؛ kcal/mol) | الديناميكا الحرارية القياسية؛ ΔG ≈ −RT·lnKa |
| `stokes_einstein` | D = kT/(6πηr) | Einstein 1905؛ SI: r(m)، η(Pa·s)، D(m²/s) |
| `arrhenius_ratio` | k₂/k₁ = exp(−Ea/R × (1/T₂ − 1/T₁)) | Arrhenius 1889 |
| `vant_hoff_ratio` | ln(K₂/K₁) = −ΔH/R × (1/T₂ − 1/T₁) | van't Hoff |
| `fick_flux` | J = D·A·ΔC/Δx | Fick 1855 (انتقال غشائي) |

### U3 — `chem_core` : الكيمياء

| العملية | المعادلة | المصدر |
|---|---|---|
| `validate_smiles` / `canonical` | تحليل وتوحيد RDKit | RDKit 2026.09 |
| `descriptors` | MW، cLogP (Crippen)، TPSA (Ertl)، HBD/HBA، روابط دوارة، ذرات ثقيلة | RDKit: Crippen 1999، Ertl 2000 |
| `lipinski` | قواعد الخمس: MW≤500 · cLogP≤5 · HBD≤5 · HBA≤10 | Lipinski 1997 (Adv. Drug Deliv. Rev.) |
| `ionization_fraction` | حمض: 1/(1+10^(pH−pKa)) · قاعدة: 1/(1+10^(pKa−pH)) | Henderson-Hasselbalch |
| `physchem_bridge` | جسر واحد إلى `core/physchem.physchem_vector` (نمط «تثبيت الجسر الواحد») | الطبقة التعليمية للمنصة |

### U4 — `pharmaceutics_core` : الصيدلانيات

| العملية | المعادلة | المصدر |
|---|---|---|
| `higuchi_k` | Q = k·√t (ميل كامل البيانات) | Higuchi 1961/1963 |
| `korsmeyer_peppas` | Q = k·tⁿ (الميل والأس عبر اللوغاريتمات؛ n≤0.89 أسطواني) | Korsmeyer & Peppas 1983 |
| `first_order_k` / `zero_order_rate` | Q(t)=Q∞(1−e^(−kt)) · Q = Q₀ + k·t | نمذجة الانحلال القياسية |
| `dose_number` | D₀ = Dose/(Cs×V) (V=250mL افتراضياً) | Löbenberg & Amidon 2000 (BCS) |
| `bcs_class` | خريطة (D₀، نفاذية) → I/II/III/IV | Biopharmaceutics Classification System |
| `cockcroft_gault` | CrCl = ((140−عمر)×وزن)/(72×SCr) ×(0.85 للإناث) | Cockcroft & Gault 1976 |
| `loading_dose` | LD = Cp·Vd/F | Rowland & Tozer |
| `maintenance_rate` | معدل الجرعة = CL·Css/F | Rowland & Tozer |
| `infusion_css` | Css = معدل التسريب/CL · زمن 95% ≈ 4.32×t½ | Rowland & Tozer |
| `pediatric_dose` | جرعة = وزن×mg/kg | الممارسة المعيارية |

### U5 — `pharma_core` : الفارماكولوجيا

| العملية | المعادلة | المصدر |
|---|---|---|
| `hill_effect` / `ec50_from_effect` | E = Emax·Cʰ/(EC50ʰ+Cʰ) | Hill 1910؛ Goutelle 2008 (JPKPD) |
| `therapeutic_index` | TI = TD50/ED50 | المعيارية |
| `certain_safety_factor` | CSF = TD₁/ED₉₉ | المعيارية |
| `cheng_prusoff_ki` | Ki = IC50/(1+[L]/Kd) | Cheng & Prusoff 1973 |
| `cyp_lookup` | قاعدة معرفة ثابتة مُعلنة (مثبطات/محفزات/ركائز) | أمثلة FDA Guidance: Clinical Drug Interaction Studies (2020) — إدخالات محدودة وموثوقة فقط |
| `ddd_lookup` | قيم DDD معلنة لثمانية أدوية شائعة (فموية) | WHO ATC/DDD Index — قيم منشورة قابلة للمراجعة حرفياً |

## 4. المرحلة الثانية — الأمراض والتشخيص

### ما ينفَّذ الآن (بذرة P19) — `diagnostics_seed`
الرياضيات البايزية للتشخيص **حتمية بالكامل** ولا تنتمي لمعرفة سريرية:
- `ppv_npv`: PPV = Se·π/(Se·π + (1−Sp)(1−π)) · NPV = Sp(1−π)/((1−Se)π + Sp(1−π))
- `likelihood_ratios`: LR⁺ = Se/(1−Sp) · LR⁻ = (1−Se)/Sp
- `post_test_probability`: احتمال بعد الاختبار من LR (تحويل الأرجحية)
- `kappa`: اتساق كوهين من جدول 2×2

### حدود المرحلة (تدهور صادق — مُعلن)
- Ryko **لا يشخّص ولا يوصي علاجاً** — يحسب الاحتمالات من مدخلات المستخدم المُعلنة (حساسية/نوعية/انتشار).
- خريطة الأمراض والعلامات والفحوص (ICD-11، قواعد الارتباط) = **P21** — قاعدة معرفة مُدقَّقة المصدر، لا توليد حرّ.
- نموذج لغة مساعد للتفسير = **P22** — خلف بوابات الإيصال نفسها (النموذج يشرح، المعادلة تحسب).

## 5. المعمارية

```
pharma_sdl/ryko/
├── __init__.py          # RYKO_VERSION + خريطة الوحدات
├── errors.py            # RykoError ثنائية اللغة (Input/UnknownOp)
├── receipts.py          # RykoReceipt + verify_stored (بصمة SHA-256 حتمية)
├── math_core.py         # U1
├── physics_core.py      # U2
├── chem_core.py         # U3 (جسر RDKit + core/physchem)
├── pharmaceutics_core.py# U4
├── pharma_core.py       # U5 (+ قواعد معرفة CYP/DDD المعلنة)
├── diagnostics_seed.py  # مرحلة 2 — البذرة البايزية
└── engine.py            # RykoEngine: سجل العمليات + الحاكم + الإيصال
```

**واجهة API** (نفس البوابة، نفس المصادقة وحد المعدل):
- `GET  /api/v1/ryko/catalog` — كتالوج الوحدات والعمليات (معادلة + مصدر + مدخلات لكل عملية)
- `POST /api/v1/ryko/compute` — `{module, op, inputs}` → إيصال كامل (قيمة + معادلة + مصدر + افتراضات + `extra` + `digest`)
- خطأ مدخل → 422 مع الرسالة الثنائية · عملية غير معروفة → 404

**حاكم ما قبل الحساب** (مستوحى من حاكم ZYKO): كل عملية تعلن نطاقات مدخلاتها؛ أي مدخل خارج النطاق يرفض قبل أي حساب — والرفض مُعلَّل ثنائي اللغة.

## 6. بوابات الجودة (اختبارات ملزمة)

1. **تحقق ذهبي مُحسوب يدوياً** لكل معادلة (مثلاً: Kd=1µM ⇒ ΔG≈−8.185 kcal/mol عند 298.15K؛ ke=0.231/h ⇒ t½≈3.0h؛ Se=Sp=0.9, π=0.1 ⇒ PPV=0.5).
2. **اختبار الحتمية**: نفس الإيصال مرتان ⇒ نفس البصمة بالبايت.
3. **اختبار التلاعب**: تعديل قيمة في إيصال مخزّن ⇒ `verify_stored` يفشل.
4. **اختبار التدهور الصادق**: كل حد نطاق ⇒ خطأ مُعلَّل ثنائي اللغة (لا صمت ولا رقم مُختلق).
5. **حارس الاتساق يتوسع**: `pharma_sdl.__version__` و`RYKO_VERSION` مقيدان بمصدر الحقيقة (`pyproject.toml`) — إغلاق ثالث انجراف مكتشف (كان `__version__` عالقاً على 0.14.0).
6. **ruff نظيف** + المجموعة الكاملة خضراء بلا شبكة.

## 8. الموقع التنافسي (ملخص — التفصيل في `COMPETITIVE-ANALYSIS.md`)

المنافسون المعتمدون: **ChemCrow / Coscientist / Google AI co-scientist** (وكلاء LLM للكيمياء)، **DeepChem / TorchDrug** (تعلم آلي كيميائي)، **ADMETlab 3.0 / ADMET-AI / pkCSM / ADMET Predictor** (ADMET)، **BioMedLM / Med-PaLM** (نماذج لغة طبية).

الميزة الفريدة لـ Ryko: **الوحيد الذي يعطي إيصالاً حتمياً قابلاً للتحقق دون اتصال لكل رقم علمي — بالعربية أولاً — بلا مفاتيح ولا شبكة**. الوكلاء LLM أقوى في التوليد والاستكشاف لكن أرقامهم غير قابلة للتحقق بطبيعتها؛ أدوات ADMET أقوى في التنبؤ بالسطوح الكيميائية لكنها لا تجيب أسئلة الجرعة والانحلال والاحتمال التشخيصي. Ryko يملأ هذه الفجوة فوق منصة اكتشاف كاملة.
